ONE AGENT LOOPS — MORE THAN ONE NEEDS A GRAPH

A Single Agent

One node, one self-loop. It plans, acts, observes, and repeats — no topology to design, because there's nothing to wire together.

VS

A Graph of Agents

Multiple nodes, deliberate edges. Topology, handoffs, and state become explicit engineering decisions — which is what this list is for.

SIX PATTERNS

Topology Patterns

The shapes multi-agent systems actually take in production — pick the pattern before you pick the framework.

01

Orchestrator–Worker

Central agent dispatches subtasks to specialized workers, then synthesizes the results.

02

Hierarchical

Manager-of-managers: a top orchestrator delegates to sub-teams, each with its own supervisor.

03

Sequential Pipeline

Fixed, linear order — each agent consumes the previous one's output. Simplest to reason about.

04

Mesh / Swarm

Peer agents hand off work directly to each other — no central controller, emergent behavior.

05

Blackboard

All agents read/write one shared workspace; the state itself decides who acts next.

06

Market / Debate

Independent proposals critique each other over rounds, converging via structured argument.
